# ADR 0002：人物印象（长期记忆）全局共享，不按会话隔离

- 状态：已定（默认行为，可用配置切换）
- 日期：2026-09-30（补记已有决策；`memory.visibility` 为其上的可选项）

## 背景

人物记忆存在全局库里（`global-person-memory-store`），键是 QQ 号，不是会话。
同一个人在 A 群和 B 群的印象**合并**成一份；模型看到的"对某人的长期印象"默认不区分来源会话。

## 决策

1. **默认全局共享**（`memory.visibility.mode = 'global'`，`hidePrivateInGroup = false`）——
   与历史行为逐字一致，升级不改变任何行为。
2. 需要隔离时由运营者显式开启：`perChat` 只保留来源含当前会话的印象；
   `hidePrivateInGroup` 在群聊里剔除来自私聊的印象。过滤按**印象条**（`sourceChatKeys`）判定，
   不按人 —— 否则"同一人在两个群各有印象"会退化成"要么全给要么全不给"。
3. 同样的策略对 `memory_query` 工具生效，工具描述随策略动态生成。

## 理由

1. **机器人的"人味"来自连续性**：同一个人在私聊和在群里表现一致，才像认识他；
   按会话切碎会表现成"换个地方就不认得你了"。
2. **隔离是隐私需求，不是默认需求**：只有运营者知道自己的群构成（是否有不该互相看见的群），
   所以默认取"与现状一致"，把判断权交回运营者。
3. **默认即现状**是这个项目的硬规矩：任何新配置项默认值必须等于升级前的行为，
   否则一次升级就会改变已经在跑的行为。

## 后果

- 开启 `perChat` 后，模型对某人的印象会变少（每个会话只看到本会话来源的那些），
  这是预期内的取舍，不是 bug。
- 过滤发生在**注入提示词之前**与 `memory_query` 查询时，落库数据不变 ——
  改回 `global` 不丢任何印象。
